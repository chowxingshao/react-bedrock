# Generators (Plop)

`pnpm gen` opens a menu. Skip the prompts by passing every answer, in order. A script or a CI job has no terminal to prompt in, so it must pass them all:

| Command                                                       | Creates                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `pnpm gen feature <plural> <singular> <y\|n>`                 | `src/features/<plural>/` with types, Zod schema, API service, query keys, hook, list page and test, index; `src/locales/<locale>/<plural>.json` for every folder in `src/locales`; a mock API in `src/mocks/handlers/<plural>.ts`. With `y`, also a route, a `paths` entry and a sidebar link. It registers the namespace in `src/core/i18n/resources.ts` and the handlers in `src/mocks/handlers.ts`. |
| `pnpm gen component <name> <ui\|feedback\|feature:<feature>>` | Component, Storybook story and test, in `src/components/ui`, `src/components/feedback` or `src/features/<feature>/components` (the feature must exist; its story is titled `Features/<Feature>/<Component>`, so two features can each have a `status-badge`)                                                                                                                                           |
| `pnpm gen page <name> <Title>`                                | `src/app/routes/<name>.tsx`, registered in `paths.ts` and `router.tsx`, with its title in every locale                                                                                                                                                                                                                                                                                                 |
| `pnpm gen hook <name>`                                        | `src/hooks/use-<name>.ts` plus a test                                                                                                                                                                                                                                                                                                                                                                  |
| `pnpm gen store <name>`                                       | `src/stores/<name>-store.ts` with selector hooks, plus a test                                                                                                                                                                                                                                                                                                                                          |

- **Names** are lower-case words joined by single dashes (`purchase-orders`). A word after a dash starts with a letter, so `s3-buckets` and `order-v2` work and `top-10-items` is refused (it would give the identifier `top_10Items`). Anything else is refused. Quote a title that has spaces: `pnpm gen page audit-log "Audit log"`.
- **Nothing is overwritten, and nothing is half-written.** Before the first write, a generator checks that none of its files exists and that each anchor it uses (below) is in place exactly once. `feature` also checks that its namespace is free in `resources.ts` and its `<name>Handlers` identifier in `src/mocks/handlers.ts` (with a route: also `paths.<name>`, the `<Name>Icon` identifier in `navigation.ts` and a `nav.<name>` key in each locale), `page` that its name is free in `paths.ts` and as a `pages.<name>` key in each locale, and `component` that its feature folder exists. When a check fails it lists every problem and writes nothing.
- **Names in the output:** files and folders use the kebab-case name, identifiers use its other cases. `purchase-orders` gives `src/locales/<locale>/purchase-orders.json` and `src/mocks/handlers/purchase-orders.ts`, but the i18n namespace `purchaseOrders` (`t('purchaseOrders:list.title')`), `paths.purchaseOrders`, `nav.purchaseOrders`, `purchaseOrdersHandlers` and `usePurchaseOrders`.
- **Output is lint-clean:** every generator ends by running `eslint --fix` and then Prettier on the files it touched.
- **Languages are the folders in `src/locales`.** `feature` writes one namespace file per folder, imports it in `resources.ts` and registers it there; `feature` and `page` write their labels into every folder's `common.json`. Adding or removing a language needs no change to the generators (docs/i18n.md, "Adding a language"), but each folder needs its own anchor in `resources.ts`: `// plop:resources-<code>`, inside that locale's block. `feature` refuses to run, and says what to add, when a folder has none; `feature` and `page` refuse when `src/locales` has no folder at all.
- **Anchors:** generators insert code at `// plop:…` comments (`resources-imports`, one `resources-<code>` per locale folder, `handlers-imports`, `handlers`, `paths`, `routes`, `nav-imports`, `nav`) and into the `"nav"` / `"pages"` objects of every locale's `common.json`. An anchor is a whole line of its own: a comment that merely mentions one does not count. **Don't delete or rename them**: `src/test/plop-anchors.guard.test.ts` fails when one is missing or appears twice, and when a locale folder lacks its `resources-<code>` anchor.
- **After generating:**
  - translate the strings of the non-English locales (names, titles and sidebar labels start as copies of the English ones)
  - add permissions: the strings in `src/config/permissions.ts`, a `<RequirePermission>` in the route module, the permission in the demo users' lists in `src/mocks/fixtures/users.ts` (their permissions are explicit lists: without it both demo accounts see "Access denied" on the new page in `pnpm dev`), and `permission` on the sidebar entry in `src/app/navigation.ts` (the generated entry has none, so its link shows for everyone). The mock handler can check it too, like `forbiddenUnless` in `src/mocks/handlers/items.ts`
  - replace the demo mock data
  - a new store: add it to the reset list in `src/test/setup.ts`, which the generator does not touch (docs/state-management.md)
- **Templates** live in `plop/templates/<generator>/*.hbs`. To change what gets generated, change the template. Each locale file of `feature` comes from `plop/templates/feature/locale.json.hbs` (English); a `locale.<code>.json.hbs` next to it replaces that text for one language (`locale.es.json.hbs` does). Avoid a literal `{{` in template code; write `{ {` and let Prettier join it. CI runs every generator and then the full gate (the `generators` job in `.github/workflows/ci.yml`: lint, typecheck, test and build).
