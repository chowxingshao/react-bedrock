# Generators (Plop)

`pnpm gen` opens a menu. Skip the prompts by passing every answer, in order. A script or a CI job has no terminal to prompt in, so it must pass them all:

| Command                                                       | Creates                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm gen feature <plural> <singular> <y\|n>`                 | `src/features/<plural>/` with types, Zod schema, API service, query keys, hook, list page and test, index; `src/locales/{en,es}/<plural>.json`; a mock API in `src/mocks/handlers/<plural>.ts`. With `y`, also a route, a `paths` entry and a sidebar link. It registers the namespace in `src/core/i18n/resources.ts` and the handlers in `src/mocks/handlers.ts`. |
| `pnpm gen component <name> <ui\|feedback\|feature:<feature>>` | Component, Storybook story and test, in `src/components/ui`, `src/components/feedback` or `src/features/<feature>/components` (the feature must exist)                                                                                                                                                                                                              |
| `pnpm gen page <name> <Title>`                                | `src/app/routes/<name>.tsx`, registered in `paths.ts` and `router.tsx`, with its title in every locale                                                                                                                                                                                                                                                              |
| `pnpm gen hook <name>`                                        | `src/hooks/use-<name>.ts` plus a test                                                                                                                                                                                                                                                                                                                               |
| `pnpm gen store <name>`                                       | `src/stores/<name>-store.ts` with selector hooks, plus a test                                                                                                                                                                                                                                                                                                       |

- **Names** are lower-case words joined by single dashes (`purchase-orders`); anything else is refused. Quote a title that has spaces: `pnpm gen page audit-log "Audit log"`.
- **Nothing is overwritten, and nothing is half-written.** Before the first write, a generator checks that none of its files exists, that each anchor (below) is in place exactly once, and that the name is free in `paths.ts` and `resources.ts`. When a check fails it lists every problem and writes nothing.
- **Output is lint-clean:** every generator ends by running `eslint --fix` and then Prettier on the files it touched.
- **Anchors:** generators insert code at `// plop:…` comments (`resources-imports`, `resources-en`, `resources-es`, `handlers-imports`, `handlers`, `paths`, `routes`, `nav-imports`, `nav`) and into the `"nav"` / `"pages"` objects of `common.json`. **Don't delete or rename them**: `src/test/plop-anchors.guard.test.ts` fails when one is missing or appears twice.
- **After generating:**
  - translate the Spanish strings (names, titles and sidebar labels start as copies of the English ones)
  - add permissions (`src/config/permissions.ts`) plus `<RequirePermission>` in the route module
  - replace the demo mock data
  - a new store: add it to the reset list in `src/test/setup.ts`, which the generator does not touch (docs/state-management.md)
- **Templates** live in `plop/templates/<generator>/*.hbs`. To change what gets generated, change the template. Avoid a literal `{{` in template code; write `{ {` and let Prettier join it. A CI job that runs every generator and the full gate is planned.
